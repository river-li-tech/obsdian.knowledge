# AI最大的价值
房间服务开发很多需求并不是 CRUD
AI 在这里的价值是做**结构化思考辅助**
不是让 AI “写方案”，而是让它作为**方案审稿人、风险枚举器、边界条件补充器**
最优策略不是追求 AI 全自动开发，而是把 AI 放在这几个位置：
- **知识入口**
- **方案审稿人**
- **测试补全器**
- **排障助手**
- **CR 风险提示器**
- **经验沉淀器**

# 构建分层工作流
构建一套覆盖以下链路的增强系统：
1.  **知识获取层**：快速理解历史方案、协议、接口、事故、设计约束
2.  **研发辅助层**：需求拆解、方案评审、代码生成、重构、测试补全
3.  **联调排障层**：日志归因、问题定位、上下游影响分析、回归范围识别
4.  **质量保障层**：代码审查、风险扫描、测试建议、变更影响评估
5.  **团队沉淀层**：把个人经验沉淀为团队可复用的 prompt、知识库、自动化 agent

所以，真正有效的路径不是上来就搭一个 “大而全的 AI 平台”，而是：
>  **从高频、低风险、可验证的研发环节切入，让 AI 先成为 “副驾驶”，再逐步变成 “流程节点”**


# 高价值场景
## 1. 复杂系统理解与知识检索
- 目标：wiki + 文档标签体系
- 至少涵盖
	- **代码库语义检索**
	- **设计文档 / RFC / 事故复盘的 RAG**
	- **会议纪要 / IM 讨论的检索**
	- **接口协议和数据结构的统一知识入口**

## 2. 需求分析与技术方案设计辅助
- 目标：AI 在这里的价值是做**结构化思考辅助**
- 不是让 AI “写方案”，而是让它作为**方案审稿人、风险枚举器、边界条件补充器**。
- 让 AI 在方案阶段帮你固定输出以下内容：
	1. 需求摘要
	2. 当前约束
	3. 核心技术风险
	4. 状态变化路径
	5. 失败场景枚举
	6. 客户端 / 服务端 / 网关 / 同步层职责划分
	7. 灰度与回滚方案
	8. 监控埋点建议
	9. 测试点清单

## 3. 编码与重构辅助
- 应该**谨慎使用、限定范围**，把 AI 用在 “**80% 机械工作 + 20% 人工裁决**” 的环节。
- 不建议完全放给 AI 的部分：
	- 核心同步协议设计
	- 高并发关键路径的性能逻辑
	- 涉及安全、权限、资金、稳定性红线的核心逻辑
	- 跨服务事务语义和复杂状态机核心实现

## 4. 测试生成与质量增强
- 训练 AI 站在 “**故障制造者**” 的视角，而不是 “happy path 编码者” 的视角
- 建议固定一组测试维度：
	- 单元测试用例枚举
	- 边界条件挖掘
	- 状态机迁移测试
	- 协议兼容性测试清单
	- 弱网、乱序、重复包、丢包、超时场景设计
	- 回归测试建议
	- 基于 bug / 事故自动反推测试补丁

## 5. 联调、排障与事故处理
- AI 可以在这里充当**日志分析助手 + 根因假设生成器 + 排查路径规划器**。
- 把过去事故复盘沉淀成一个 “**故障模式库**”：
	- 现象
	- 根因
	- 识别信号
	- 快速验证方法
	- 规避方案
	- 后续监控项

## 6. Code Review 与变更风险控制
- 影响面分析
	- **变更影响分析**
	- **兼容性检查**
	- **并发 / 时序风险识别**
	- **异常路径缺失检查**
	- **监控埋点遗漏检查**
	- **回滚难度提醒**
	- **协议字段演进检查**
